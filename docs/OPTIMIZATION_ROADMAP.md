# 后续优化方向

> 作业交付文档之五。配套：[使用说明书](./USER_GUIDE.md)｜[测试报告](./TEST_REPORT.md)｜[技术架构](./TECHNICAL_ARCHITECTURE.md)

本文提出 **5 个**可进一步提升 Agent 性能的方向。Critic、编排、bench、证据优先竞品分析（方案2）等已落地能力见[技术架构](./TECHNICAL_ARCHITECTURE.md)，不在此重复罗列。

---

## 建议落地顺序

`① 看板金样评测 → ② 5118 热度进 Feed → ③ 语义分类器 → ④ 结构化 Handoff / Critic 复检 → ⑤ 投后校准回灌`

先保证「改了不退化」，再扩数据与语义能力，最后做多轮越用越准。

---

## ① 对标看板事实/行动双轨金样评测｜P0

| 维度 | 内容 |
| --- | --- |
| **为何做** | 换 Prompt/模型后只能肉眼看「像不像投手 briefing」；方案2 事实层改动缺少自动红灯 |
| **做法** | 固化珍妮+曲奇看板金样 `bench/fixtures/board_copy_golden.json`；事实字段硬断言，行动建议另轨打分；CI 无 Key 可跑 |
| **验收** | 篡改「现金∈信任」必挂；只改行动文案不挂事实轨 |

---

## ② 5118 / 合规热度接入 FeedAdapter｜P0

| 维度 | 内容 |
| --- | --- |
| **为何做** | 模块6 热点监控仍偏人工粘贴或 Mock；投手无法定时看真实搜索热度再决定跟进 |
| **做法** | 将 `scripts/fetch_keyword_heat.py` 封装为 `FeedAdapter.pull()`；daemon 定时落库；有非 mock 源时改写 `data_source_status` |
| **红线** | 正式指数标 `B_5118_live`，下拉代理标 `C_proxy_suggest`；**禁止**写成小红书官方热搜 |
| **验收** | 无人工粘贴时模块6 仍能给出带来源的跟进建议 |

---

## ③ 语义分类器替代词表分桶（原方案3）｜P1

| 维度 | 内容 |
| --- | --- |
| **为何做** | 确定性词表对新品类/新话术扩展慢；「现金」「假店」等依赖语境 |
| **做法** | Embedding 或小模型对每条竞品笔记分类 → 维度标签 + 信息点；**聚合/门槛/结论分级仍走方案2 确定性层** |
| **红线** | 失败或无 Key → 回退规则；缓存保证可复现；分类器不得改写 `coverage` / `conclusion_type` |
| **验收** | 珍妮金样不退化；离线模式与方案2 一致 |

---

## ④ 结构化 Handoff + Critic 重写后复检｜P1

| 维度 | 内容 |
| --- | --- |
| **为何做** | 下游只吃 ≤600 字文本易丢空白分级/高峰槽；Critic high→重写已有，但缺二次复检 |
| **做法** | M1→M2 / M1→M4 / M6→M3 增加 Pydantic `Handoff*`；high 重写后再跑精简 Critic |
| **验收** | M2 可点名引用 M1 高潜空白；故意注入值班表时段文案后复检通过或降至 medium 以下 |

---

## ⑤ 投后效果回流 → Agent 默认档校准（不碰护栏）｜P1

| 维度 | 内容 |
| --- | --- |
| **为何做** | 第二轮投放仍大量依赖首轮默认探测预算/参考 CTR |
| **做法** | 周级效果表导入 → `calibration=ready` 时写入 M4/M5 证据区与工具默认；报告增加「相对历史」；出价/止损倍率**只提示人工复核** |
| **验收** | 导入 ≥4 周样例后校准 ready 且报告有相对历史；无导入时行为与现网一致 |

---

## 明确不做

- 不爬小红书全站热搜、不绕过登录/验证码。  
- 不把 5118 指数宣传为「小红书热搜」。  
- 不自动放宽出价/止损硬护栏。  
- 本阶段不做生产级多租户 IAM/计费（演示级 `brand_id` 可另立项）。
