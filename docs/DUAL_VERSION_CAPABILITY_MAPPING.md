# 代码版与 Claude/GPT 零代码版能力映射

本文以 `docs/TECHNICAL_ARCHITECTURE.md` 的当前代码架构为准，说明可运行代码版与
Claude Project/Custom GPT 零代码版之间的能力对应关系。零代码版依靠知识文件、固定
提示词、结构化输出模板和人工复核来补偿平台无法自动执行的部分，不能被描述为与本地
服务具有相同的校验、状态库或自动化保证。

六模块的目标业务依赖 `M1 → M2 → M6 → M3 → M4 → M5` 仍是计划中的显式编排；当前
运行时确定性基线和可选 Agent 附加按数值顺序 `M1 → M2 → M3 → M4 → M5 → M6` 执行。
当前运行时的数字计算和报告内容以请求证据为输入，不代表已经实现目标依赖交接。

## 使用边界

- 代码版是运行事实的来源；零代码版是受证据、模板和人工审批约束的协作替代方案。
- `Analyzer` 的可选调用不改变确定性基线、证据审计、数字溯源和 Mock 隔离的边界。
- `Embedding` 在代码版已参与混合检索；无有效 Key 时使用本地向量兜底，不得把兜底写成与远程模型同等语义质量。
- 目标模块依赖属于计划中的编排演进；任何版本都必须在前置证据或模块产物缺失时显式报告差距。
