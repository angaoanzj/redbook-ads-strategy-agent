# Production Readiness

本项目按三个阶段交付：Demo、试投、生产。阶段边界比“是否能启动”更重要：只有真实数据、权限、审批和持续监控都满足，才可以进入生产投放。

## 阶段一：Demo

适合面试演示、产品评审和离线回归。

- 可使用固定案例或 Mock 数据生成六模块策略报告。
- Mock 数据必须带 `is_mock=true`、`evidence_grade=M` 和 `mock_seed`。
- 竞品预算、达人名单、热搜、CPC/CPM/CPA 不得当作真实平台事实。
- 允许未配置模型 Key 时使用确定性引擎演示。
- SQLite 会话状态和 Session Memory 可用于展示多轮上下文，但不承载真实账户权限。

## 阶段二：试投

适合小预算、人工审批、可回滚的验证性投放。

- 优先上传聚光导出的 CSV 或 JSON 历史报表；最低字段见 `docs/USER_GUIDE.md` 的账户诊断说明。
- 使用真实账户指标替换 Mock 基准，并保留来源、期间、单位和计算口径。
- 先用自然内容筛选素材，再使用有限预算验证搜索、信息流和达人相似定向。
- 每次预算迁移必须由投手确认，不由 Agent 直接改写聚光账户。
- 记录素材、计划、单元、推广目标、消耗、点击、转化和成交金额，确保建议可复盘。
- 高风险动作继续使用人工审批；Session Memory 只能辅助“继续上次方案”等低风险消歧。

## 阶段三：生产

适合持续运营和规模化预算管理。

- 接入经授权的聚光账户数据源或稳定的报表同步任务，并完成字段映射、失败重试和数据新鲜度监控。
- 对 CPC、CPM、CTR、CVR、CPA、ROI 建立品牌/品类/周期基准，禁止用演示常量替代账户事实。
- 对计划、单元、创意、人群、搜索词和预算迁移建立审计日志与人工审批记录。
- 生产环境的 Session Memory 使用 SQLite 以外的共享存储或经过验证的数据库方案，配置 TTL、容量上限、并发控制、备份和清理任务。
- 敏感数据采用内容级脱敏与审计，禁止保存 Cookie、Authorization、API Key、账户令牌、个人联系方式和审批凭据。
- 监控数据源延迟、分析失败率、Mock 占比、未溯源数字、预算守恒、模型成本和异常告警。
- 生产发布前必须完成真实脱敏案例回归、权限测试、恢复测试和人工止损演练。

## 当前状态与缺口

当前代码已具备本地可运行原型、SQLite 会话持久化、幂等记录、缓存 TTL、WAL/事务保护、Mock 隔离和证据边界。Session Memory 现支持当前会话内的品牌、产品、品类、目标、最近报告、意图和低风险币种偏好，并通过 `/sessions/{session_id}/memory` 查看。

仍需补齐：

1. 聚光真实账户数据/API 接入和账户诊断模式的完整报表链路；
2. 多实例部署下的共享 Session Memory、备份和清理任务；
3. 内容级手机号、地址、联系方式和业务凭据审计；
4. 预算迁移建议的线上实验和真实账户校准；
5. 生产级权限、审批、告警和操作审计；
6. 完整依赖环境下的全量测试与脱敏回归数据。

在这些缺口关闭前，本项目的定位仍是 Demo/试投决策辅助工具，不是自动投放器。
