# 数据检索逻辑与字段审计

审计日期：2026-07-24

## 结论

当前检索链路“能运行，但不够严谨”。它适合召回公开笔记样本，不适合直接支撑品牌、竞品、投放和生意数据的统一分析。最大问题不是缺少字段数量，而是：真实投放表没有接入 `/analyze`，检索没有按时间、来源、证据等级和数据类型过滤，笔记检索使用“任一词命中 + 互动量加权”，容易把高互动但弱相关内容排到前面。

## 一、当前数据流

```text
CampaignRequest
  ├─ category/product/selling_points → KnowledgeBase.search()
  ├─ competitor_candidates → identify_competitors()
  └─ official rules → get_official_rules(limit=20)
       ↓
main.py 合并笔记和竞品
       ↓
engine.run_strategy()
```

当前 `/analyze` 没有自动读取以下知识库表：

- `brand_products`
- `brand_profiles`
- `paid_metrics`
- `organic_metrics`
- `data_provenance`

因此 Excel 已入库不等于分析时已使用。投放指标目前仍依赖请求体中的 `benchmark_evidence` 手动传入。

## 二、检索逻辑问题

### P0：检索结果缺少时间过滤

`analysis_days` 只进入输出，不参与 `KnowledgeBase.search()` 查询。检索可能把旧笔记与近30天笔记混在一起，无法支撑“近30天趋势”和“当前赛道变化”。

### P0：投放数据没有进入分析链路

`paid_metrics` 只有 `data_json`，`_spotlight_market_summary()` 只读取 `request.benchmark_evidence`。真实 Excel 的 CPC、CPM、搜索组件转化率不会自动成为分析证据。

### P0：数据类型没有分层过滤

`notes` 查询没有按 `source_name`、`evidence_grade`、品牌/竞品、平台、地域或 `is_mock` 过滤。今后加入模拟数据后，默认检索必须显式排除 Mock。

### P1：相关性排序过于宽松

`search()` 会把查询拆词，然后任意字段命中即可获得相关性分；互动量再通过对数加分。结果可能是“互动量很高但只命中一个泛词”的笔记排在真正相关笔记之前。

### P1：没有结果多样性控制

结果只按相关性和互动量排序，没有限制同一账号、同一关键词、同一竞品或同一日期的占比，容易被单一来源淹没。

### P1：竞品识别是文本子串匹配

`identify_competitors()` 将候选品牌直接做 `key in text`，会出现品牌别名、同名词、标题偶然提及和竞品产品名混淆；也没有按 `analysis_days`、搜索关键词或来源做过滤。

### P1：官方规则按最新时间取前20，不做品类相关性匹配

规则应按食品、广告、跨境、达人合作等类别和品牌场景排序，而不是只按更新时间截断。

## 三、字段缺口

### 1. 笔记字段

现有字段：标题、正文、URL、作者昵称、互动、标签、内容类型、发布时间、采集时间、来源、证据等级。

缺少：

- 平台和语言/地区
- 账号 ID、粉丝快照、账号类型
- 曝光/阅读量、主页访问、涨粉、外链点击
- 视频时长、播放完成率
- 广告标识证据、广告截图/证据 URL、核验人、核验时间
- 评论原文及评论聚合标签
- 内容主题标签的来源和标注方式
- 指标快照时间；互动数据是否为当前快照还是发布后固定窗口
- 稳定 canonical URL 与带 token 临时 URL 的区分

### 2. 投放字段

现有 Excel 原始数据已包含月度消费、曝光、点击、CTR、CPC、CPM、点赞、评论、收藏、互动、搜索组件数据。

缺少或未结构化：

- 平台、账户 ID、计划 ID、单元 ID、素材 ID
- 投放目标、版位、搜索/信息流标识
- 开始时间、结束时间、投放时长
- 人群包 ID、定向标签、地域、年龄、性别
- 转化事件、转化数、成交订单、成交额、退款、归因窗口
- 货币和税费/服务费口径
- 素材 URL、素材版本、标题、封面、落地页
- 数据导出时间、报表口径和数据质量状态

### 3. 生意/归因字段

当前没有独立生意事实表。至少应有：

- order_id、商品/SKU、订单时间
- 订单金额、优惠、退款金额、实付金额
- 来源平台、计划、素材、笔记、达人
- 新客/老客、地域、渠道
- 归因模型和归因窗口

没有这些字段时，不应计算真实 ROAS、CPA、CAC、复购率和地域转化差异。

### 4. 竞品投放字段

现有 `CompetitorEvidence` 只有账号、URL、互动、格式、广告标识、受众观察和备注。

缺少：

- 竞品品牌/账号 ID
- 广告标识截图和核验时间
- 首次发现、最后发现、连续快照数
- 投放时长区间
- 素材版本和变化
- 推广目标、版位、人群推测证据
- 预算区间的来源和置信度
- 竞品自然内容与广告内容的关联

预算、真实定向和真实成交不能通过公开笔记直接补齐；只能标记为“不可观测”或“授权数据缺失”。

## 四、建议的数据优先级

```text
品牌授权后台/API
  > 用户导出的真实报表
  > 人工核验的公开观察
  > 仅用于演示的 Mock
```

每条检索结果必须带 `is_mock`、`evidence_grade`、`source_name`、`collected_at` 和 `as_of`。默认查询条件应是：

```text
is_mock = 0
source_type ∈ 当前任务允许范围
as_of / published_at ∈ 分析窗口（除非用户明确请求历史基准）
```

## 五、建议改造顺序

1. 将 `paid_metrics` 和 `organic_metrics` 标准化为可查询列，并接入 `/analyze`。
2. 给笔记检索增加时间、来源、证据等级、平台和多样性参数。
3. 将竞品识别改为品牌别名/实体标准化 + 证据计数，而非简单子串命中。
4. 增加投放计划、素材、人群和订单归因表；无转化字段时强制输出“不可计算”。
5. 增加 `evidence_refs`、`sample_size`、`as_of`、`confidence` 到模块结论。
6. 增加字段完整性检查，按模块生成缺口而不是只在总报告里提示。
