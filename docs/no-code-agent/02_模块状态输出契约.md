# 模块状态输出契约

每个模块结束时必须输出一个 YAML-like `module_state`。它是零代码模块之间唯一可复用的业务状态摘要；自由对话正文不是可靠状态库。代码版的持久化和程序校验更强，零代码交接必须由人工确认和文件保存补偿。

## 1. 有效 `module_state`

```yaml
module_state:
  run_id: "2026-07-25-brand-001"
  module: "M1"
  status: "completed_with_gaps"
  evidence_ids:
    - "A-001"
    - "B-004"
  confirmed_facts:
    - fact: "品牌授权报表覆盖 2026-06-01 至 2026-06-30"
      evidence_id: "A-001"
  assumptions:
    - assumption: "以 D_行业基准生成首周测试范围"
      evidence_level: "E_策略假设"
  decisions:
    - decision: "先验证三个内容角度"
      rationale: "公开观察样本有限"
  unresolved_gaps:
    - "未提供账户级 CPC 与 CPA"
  human_review_items:
    - "确认测试预算上限和合规素材"
  confidence: "medium"
  decision_source: "evidence_and_human_review"
```

字段必须存在，即使其值为空列表。`status` 只能说明完成、带缺口完成、阻塞或等待人工复核；不得以“已完成”掩盖 `unresolved_gaps`。`confidence` 必须反映证据完整性而非模型语气，`decision_source` 必须区分证据、确定性计算、策略假设、Mock 和人工确认。

## 2. 交接规则

- 后续模块只可消费前序 `module_state.confirmed_facts`、`decisions`、已选指标登记项和明确列出的 `assumptions`；不得从对话记忆补写事实。
- 对缺失的前序状态，后续模块必须声明缺失、使用允许的安全默认值或停在缺口处，并降低 `confidence`。
- 跨会话 handoff 时，操作者应保存完整 `module_state`、关联 `benchmark_registry` 和原始证据文件；新会话先粘贴/上传这些工件，再复述 `run_id`、版本和未解决缺口。
- 因为零代码平台不保证跨会话持久化、幂等或自动恢复，交接后必须由人工复核确认状态来源、文件版本与引用的证据 ID。

## 3. 禁止行为

- 不得删除 `unresolved_gaps` 或 `human_review_items` 来制造已完成印象。
- 不得把 `Mock`、`E_策略假设` 或未核验 Web Search 结果放入 `confirmed_facts`。
- 不得以状态块替代采购、下单、预算放量或达人合作的人工审批。
