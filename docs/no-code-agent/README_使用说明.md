# 小红书策略零代码包使用说明

本目录把现有策略 Agent 的业务边界整理为可在 Claude Project 或自定义 GPT 中运行的文档包。它不是账户后台、自动执行器或持久化系统；所有预算放量、达人合作、采购、下单、账户配置、合规和数据真实性都需要人工审批。

## 使用前准备

1. 先准备本次品牌输入、可追溯来源和目标期；历史指标应带原始文件、期间、单位与公式。
2. 不上传密钥、登录凭据、客户个人信息或未经授权的账户导出。没有授权材料时，保持“不可确认”。
3. 只维护一套共享业务规则：本目录的治理文件为所有 SOP、Claude Project 和自定义 GPT 共用的唯一规则集。更新治理文件或 SOP 后，两个平台必须同步替换同一版本；不要在平台 Instructions 中复制、分叉或改写规则。

## Claude Project 设置

1. 新建 Claude Project，并将 `Claude_Project_System_Prompt.md` 安装到 Project 的 **Instructions**（项目指令）区域；它是平台入口提示词，**不是普通知识文件**。
2. 按下方“上传顺序”向 Project Knowledge 添加治理文件、SOP 和本次材料。
3. 每次新对话先给出品牌输入与目标期，再输入 `/m1` 至 `/m6` 或 `/full`。需要续跑时按“跨会话交接”粘贴已保存工件。

## 自定义 GPT 设置

1. 在 GPT Builder 的 Configure 页面，将 `Custom_GPT_Instructions.md` 的正文安装到 **Instructions** 字段；它是平台入口提示词，**不是普通知识文件**。
2. 将下列治理文件、SOP 和可选材料上传到 Knowledge。Custom GPT 的检索是选择性的，运行时必须按入口提示词明确取回相应文件。
3. 只在需要补充公开、可复查资料时启用 Web Search；不要把搜索摘要当作账户数据。

## 上传顺序（必须遵守）

两种平台都按以下三批上传，先完成前一批再开始后一批。

1. **共享治理（01–04，必须先上传）**
   - `01_全局证据与数据纪律.md`
   - `02_模块状态输出契约.md`
   - `03_跨模块依赖与冲突处理.md`
   - `04_指标单一事实源规范.md`
2. **六个 SOP（必须第二批上传，按 /full 执行顺序）**
   - `模块1_赛道竞品分析SOP.md`
   - `模块2_用户画像选题SOP.md`
   - `模块6_关键词策略SOP.md`
   - `模块3_达人匹配SOP.md`
   - `模块4_聚光投流决策SOP.md`
   - `模块5_全域预算节奏SOP.md`
3. **可选数据与示例（最后上传，只补充本次事实或演示结构）**
   - `data/quartet_brand_dossier.json`
   - `data/quartet_public_sources.json`（品牌公开来源、链接与可公开核验字段）
   - `docs/QUARTET_DATA_PROVENANCE.md`（工作簿、公开来源与 Mock 的产出来源说明）
   - `examples/cookie_quartet_with_workbook_data.json`
   - `examples/cookie_quartet_full_case.json`
   - `示例_曲奇四重奏_FULL.md`

平台入口提示词只安装在 Instructions，**不是普通知识文件**，不作为普通 Knowledge 上传；其余文件才按上述顺序作为知识或本次对话附件提供。

## 命令路由与快速开始

| 命令 | 做什么 | 必须读取 |
| --- | --- | --- |
| `/m1` | 赛道与竞品公开观察边界 | 模块 1 SOP 与四份治理文件 |
| `/m2` | 测试画像与内容选题 | M1 `module_state`、模块 2 SOP |
| `/m6` | 规范关键词库 | M1/M2 `module_state`、模块 6 SOP |
| `/m3` | 达人筛选与开放名额 | M2/M6 `module_state`、模块 3 SOP |
| `/m4` | 聚光测试方案 | M1/M2/M6/M3 `module_state`、模块 4 SOP |
| `/m5` | 全域预算与节奏收口 | 所有前序状态、模块 5 SOP |
| `/full` | 完整受控流程 | 严格执行 M1 → M2 → M6 → M3 → M4 → M5 |
| `/ab` | 已完成状态的 A/B 矩阵 | 只转换结构化状态，不补造证据 |
| `/board` | 已完成状态的看板字段 | 只转换结构化状态，不补造证据 |

可直接复制的首条请求：

```text
/full
品牌输入：{品牌、产品、目标期、目标、预算、已提供证据文件}
要求：先建立 evidence_registry 和 benchmark_registry；每一步输出完整 module_state；缺私有账户数据时写“不可确认”；任何预算、达人、采购、下单或账户执行仅列人工审批项。
```

单模块续跑示例：

```text
/m4
以下是同一 run_id 的 M1、M2、M6、M3 module_state 与 benchmark_registry。请只生成待审批测试方案；不要声称拥有聚光后台、真实定向或成交数据。
```

## 跨会话交接

零代码平台不保证跨会话持久化、幂等、自动恢复或精确算术。每次模块结束后，把完整 `module_state`、关联的 `benchmark_registry`、evidence_registry 和原始输入文件保存到受控位置。新会话中先上传/粘贴这些工件，再明确写出 `run_id`、登记表版本、已完成模块和 `unresolved_gaps`；由人工核对证据 ID 与版本后再执行下一模块。自由对话摘要不能替代 `module_state`。

`evidence_registry` 的唯一根键和字段结构定义在 `01_全局证据与数据纪律.md`。交接文件不得改名为其他 registry，也不得省略来源 URL、采集时间、期间、Mock 状态、允许用途或禁止用途；未知字段用 `null` 或空列表保留。

## Web Search 与平台能力边界

Web Search 仅能发现公开且当前可复查的资料。每条观察记录 URL、访问日期、观察对象和证据标签；它不能证明竞品真实预算、真实定向、订单、转化或聚光账户事实。无法确认时必须写“不可确认”，并提出可接受的补数方式（授权报表或用户导入），不得绕过登录、验证码或访问控制。

平台不会替代代码版的数据库、程序校验和确定性计算。特别是：

- **持久化限制**：上传文件、对话记忆和检索命中都可能不完整，必须人工保存和复核状态工件。
- **算术限制**：预算归一、比例互补、阶段金额与守恒式必须按 SOP 复算；模型文本不是计算证明。
- **执行限制**：即使文本已给出方案，也不能自动创建广告计划、选择后台标签、联系达人、采购、下单或放量。

## 零代码确定性计算替代

本包不上传或执行 Python `tools/` 源文件。为保证可复算，M3、M4、M5、M6 的“执行步骤”各包含唯一的机器可读 `calculation_contract`，逐项复制当前代码的阈值、常量、公式、护栏、舍入、尾差、排序和缺数据回退：

- M3：达人层级预算、粉丝阈值、匹配分、互动率、Top 20 排序和开放名额；
- M4：聚光预算缺失回退、冷启动/放量护栏、HKD 客单价换算、测试带宽、止损与 ROI；
- M5：自然/付费及三阶段拆分、达人分层金额、冷启动/放量出价；
- M6：词数/去重/层级校验、倍率优先级和各关键词出价带。

执行这些契约时使用计算器或表格保存“输入 → 中间值 → 公式 → 结果”，并由第二人抽查。不得只写“等同某工具”；若平台不能可靠完成计算、关键输入缺失或结果不满足守恒/护栏，就按对应 SOP 降级为 `blocked`、空金额或待人工计算，而不是生成近似数字。
