# 指标单一事实源规范

所有模块共享唯一的 `benchmark_registry`。每个指标先记录候选值，再选择一个可供下游引用的值；不得让模块自行复制、改写或用模型记忆替换已选择的指标。历史事实保留精确值；未来建议、预测、出价和预算方案必须表达为范围。

## 1. 有效 `benchmark_registry`

```yaml

  version: "2026-07-25.1"
  metrics:
    CPC:
      candidates:
        - value: 2.83
```

`candidates` 必须保留每个可比较候选值的来源、期间、公式和证据等级。`selected_value`、`selected_source`、`selection_reason`、`period`、`formula` 和 `evidence_level` 缺失时，下游模块只能报告“不可确认”或使用显式的策略范围，不能编造单点事实。

## 2. 选择规则

1. 先确认公式、单位、归因口径和 `period` 可比；不可比的候选值只能并列说明。
2. 在可比前提下，优先选择目标期、目标账户的 `A_官方或授权`，其次为范围明确的 `C_用户导入`；`B_公开观察` 和 `D_行业基准` 只可作为样本/测试参考。
3. 用 `selection_reason` 说明时效性、范围和口径为何胜出，并保留未选候选值。
4. 有数值的历史事实必须标为 `value_kind: historical_fact`，并以 `value_precision: exact` 保留导入或授权来源的精确值 `selected_value`；不得把历史事实改写成范围。
5. 未来建议必须标为 `value_kind: future_recommendation`，并以 `range_representation: complementary_pairs` 的成对范围表达；每个数值配对都要携带 `evidence_id`、`evidence_level: E_策略假设`、来源、期间、公式和选择理由，且对应 ID 必须存在于同一 `evidence_registry`。每对搜索与推荐比例合计 100%，不得伪装成历史 `selected_value`。
6. `E_策略假设` 可以定义未来建议范围，但不能覆盖历史事实；`Mock` 永远不成为正式 `selected_value`。

## 3. 使用与复核

- 下游模块引用指标时必须携带登记表版本和 `selected_source`，不得只写“行业平均”或“系统建议”。
- `recommended_ratio` 与 `scenario_ratio` 是不同字段。每个 `pairs` 条目都必须以互补的 `search` 和 `feed` 表达，且 `search + feed = 100%`；不得把两个独立范围相乘或任意拼接。前者经人工审批后可进入正式预算计算，后者仅用于情景比较，不得混入正式预算。
- 报告发布前检查 CPC、CPM、CPA、CTR、CVR、ROAS 是否都引用同一版登记表；缺值、冲突或不一致必须进入 `human_review_items`。
- 任何预算、采购、下单或放量结论仍需人工复核，零代码文本不是执行指令。
