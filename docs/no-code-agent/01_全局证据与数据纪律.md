# 全局证据与数据纪律

本文件是所有零代码模块、SOP 与报告的共同约束。代码和当前技术文档是实现状态的权威来源；零代码控制较弱，任何高影响结论都需要人工复核。不得声称拥有内部小红书访问权限、账户后台权限或未提供的私有数据。Embedding 当前未接入检索链路，不能把知识文件检索描述为 Embedding 或向量召回。

## 1. 证据等级与允许结论

| 标签 | 含义 | 允许结论 |
| --- | --- | --- |
| `A_官方或授权` | 官方规则、品牌授权账户数据或书面授权材料 | 可作为指定账户、指定期间的正式事实与决策基准；仍须记录期间和来源。 |
| `B_公开观察` | 可复查的公开页面、公开笔记或公开活动页观察 | 仅可得出样本内、观察时点内的描述性结论，不得外推为平台大盘或账户事实。 |
| `C_用户导入` | 用户提供的历史报表、达人表或业务文件 | 可作为该用户声明范围内的历史事实；应保留原文件、期间和导入人。 |
| `D_行业基准` | 有明确来源和适用条件的行业报告或基准 | 可作测试区间、情景比较和保守规划参考，不得覆盖账户实测。 |
| `E_策略假设` | 为补齐方案而显式提出、尚未被证实的假设 | 只能形成待验证的测试方案、风险提示或数据收集请求。 |
| `Mock` | 显式生成或手工构造的数据模拟 | 仅用于演示、培训、原型和回归情景，必须带 `Mock` 标识。 |

## 1.1 规范 `evidence_registry`

所有入口、SOP、`/full` 交接和示例只能使用根键 `evidence_registry`；不得另建别名。`version` 与 `run_id` 标识本次登记版本，`evidence` 保存来源，`claims` 保存由来源支持或仍待补数的声明，`competitor_subjects` 保存公开观察对象。下面是唯一机器字段契约，其中 `E-RATIO-001` 只是策略假设的结构示例，不是平台历史事实：

```json
{
  "evidence_registry": {
    "version": "2026-07-25.1",
    "run_id": "example-run-001",
    "evidence": [
      {
        "id": "E-RATIO-001",
        "evidence_level": "E_策略假设",
        "source_type": "strategy_assumption",
        "source_name": "首轮搜推比例测试设计",
        "source_url": null,
        "collected_at": "2026-07-25",
        "period": "未来首轮测试",
        "status": "assumption",
        "is_mock": false,
        "allowed_use": ["待审批测试情景", "敏感性分析"],
        "prohibited_use": ["历史事实", "未审批正式预算", "账户后台事实"]
      }
    ],
    "claims": [
      {
        "id": "CLAIM-RATIO-001",
        "subject": "搜索/信息流测试比例",
        "claim_type": "future_recommendation",
        "status": "assumption",
        "value": {"search": 60, "feed": 40},
        "unit": "percent",
        "evidence_ids": ["E-RATIO-001"],
        "formal_use": false,
        "required_evidence": "人工审批记录与账户首轮测试回填"
      }
    ],
    "competitor_subjects": [
      {
        "name": "示例竞品",
        "evidence_ids": [],
        "status": "unavailable"
      }
    ]
  }
}
```

字段不能省略，未知值写 `null` 或空列表。`evidence.status` 只取 `available | unavailable | assumption | mock | conflicted`；`claims.status` 只取 `confirmed | observed | unavailable | assumption | mock | conflicted`。`evidence_ids` 必须引用同一登记表中真实存在的 ID；`formal_use: true` 只可在证据等级允许、口径可比、人工审批完成且非 Mock 时出现。公开观察、策略假设、不可用声明和 Mock 的正式用途均为 `false`。

## 2. 禁止替代与数字纪律

- **禁止替代**：不得用 `B_公开观察`、`D_行业基准`、`E_策略假设` 或 `Mock` 替代 `A_官方或授权` / `C_用户导入` 的账户事实。
- 不得把公开笔记互动、估算销量、第三方截图或模型记忆写成竞品真实预算、真实定向、成交订单或聚光账户数据。
- 每个历史数字都要带证据 ID、来源、`period`、单位和公式（如适用）；历史事实保留原始精确值。
- 未来预测、建议出价、预算分配和测试目标必须标为建议或假设，并使用范围而非伪精确单点承诺。
- `Mock` 是数据模拟，永不进入采购、下单或正式预算结论；若混入输入，必须停止此类结论并列入人工复核。

## 3. Web Search 使用边界

Web Search 只可用于发现并记录公开可复查的信息。结果必须保存 URL、访问日期、观察对象和证据等级；搜索摘要、搜索排序和无法复查的摘录不是账户事实。

当 Web Search 不能确认竞品预算、定向、订单、转化或账户指标时，输出“不可确认”，说明所缺数据及可接受的补数方式（例如授权报表或用户导入），不得以行业逻辑、模型常识或搜索片段补成事实。不得尝试绕过登录、验证码、访问控制或声称存在内部小红书访问。

## 4. 输出前最低检查

1. 将事实、观察、基准、假设和 Mock 分开列示，并为每项分配证据 ID。
2. 对每个高影响结论核对证据等级是否允许该结论。
3. 对无依据或冲突数字降级为“不可确认”或 `E_策略假设`。
4. 标出必须人工复核的预算放量、达人合作、采购、下单、合规和数据真实性事项。
