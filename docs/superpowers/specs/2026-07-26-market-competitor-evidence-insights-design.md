# 赛道与竞品深度分析：证据化洞察升级设计

日期：2026-07-26

## 1. 背景与问题

现有「赛道与竞品深度分析」同时包含确定性引擎、看板拼装和可选 LLM Agent。当前竞品共性表的部分结论由关键词命中直接拼装：

- 「信息密度」输出孤立词语，而非可读的信息组合；
- 「现金」被同时当作交易条件和信任机制；
- 用户画像被直接当作「互动引擎」；
- 「假店」一词被无条件归入扩散风险；
- 自有卖点未出现在少量竞品样本中，就被升级成「内容空白」；
- 结论缺少样本量、覆盖率、证据来源和置信度。

这些问题不只来自 Prompt。离线确定性引擎会直接生成相同的薄弱结论，因此必须同时优化证据计算、输出结构、Prompt 和测试。

## 2. 目标

在保持现有 API 和前端兼容的前提下，把证据化竞品洞察直接融入现有「赛道与竞品深度分析」：

1. 无模型 Key 时也能生成可信、可读、可解释的竞品分析；
2. 明确区分事实、推断、待验证假设和证据不足；
3. 每项结论提供样本数、覆盖率、证据摘要、置信度和缺失证据；
4. 不再把样本内未出现直接等同于市场空白；
5. LLM 只补充行动建议，不覆盖确定性事实；
6. 以项目内珍妮曲奇手工优质版为表达质量金样，但所有自动结论必须由当前输入证据支持。

## 3. 非目标

- 不新增独立页面或独立竞品工具；
- 不改变「赛道与竞品深度分析」现有入口和章节结构；
- 不声称少量公开样本代表全平台大盘；
- 不从点赞、收藏或评论量反推竞品真实预算；
- 不在本次改造中引入新的外部 Embedding、分类模型或数据供应商。

## 4. 方案选择

采用「证据优先的确定性分析＋可选 LLM 行动建议」。

未采用的方案：

- Prompt 优先：无法改善无模型 Key 时的确定性输出；
- 语义分类器优先：增加成本、依赖和不可重复性，当前收益不足。

## 5. 架构与数据流

```text
CompetitorEvidence[]
    ↓
逐条证据信号提取
    ↓
按维度聚合、去重、计算覆盖率
    ↓
样本门槛与结论分级
    ↓
兼容版 commonality_rows
    ↓
赛道与竞品深度分析看板 / Markdown 报告
    ↓
可选 LLM 行动建议（不得覆盖事实层）
```

新增一个职责单一的分析模块，负责把 `CompetitorEvidence[]` 转成结构化洞察行。看板文件只负责渲染和兼容映射，不再承担关键词分类业务逻辑。

## 6. 兼容输出契约

现有消费者继续读取：

```json
{
  "dimension": "互动引擎",
  "observation": "价格与支付规则引发咨询；真假门店信息促进收藏和求证"
}
```

同一行新增可选字段：

```json
{
  "dimension": "互动引擎",
  "observation": "价格与支付规则引发咨询；真假门店信息促进收藏和求证",
  "evidence": [
    {
      "account": "詹詹的市井日记",
      "title": "香港珍妮曲奇 好吃程度排序",
      "signal": "评论高频问价格、机场和现金支付",
      "source": "notes/observed_audience"
    }
  ],
  "sample_count": 2,
  "total_samples": 3,
  "coverage": 0.667,
  "conclusion_type": "inference",
  "confidence": "low",
  "missing_evidence": ["缺原始评论逐条样本"]
}
```

字段约束：

- `dimension`、`observation` 保持兼容；
- 新字段全部为增量字段；
- 没有证据的维度仍保留一行，`conclusion_type=evidence_insufficient`；
- `confidence` 只允许 `low`、`medium`、`high`；
- 小于 5 条竞品样本时，任何跨样本结论的置信度最高为 `low`。

## 7. 维度判定规则

### 7.1 选题

- 至少在 2 条样本中出现，才能称为「共性」；
- 只在 1 条出现时写为「单篇观察」；
- 结论展示主题覆盖数量和代表笔记。

### 7.2 信息密度

- 识别地址、交通、营业时段、价格、支付、排队、限购、规格、推荐清单等决策信息点；
- 输出信息组合和对应样本，不输出孤立关键词串；
- 「信息密度高」必须有同一笔记覆盖多个不同信息点的证据。

### 7.3 信任机制

- 仅包括可降低购买风险的机制：官方门店依据、真假辨别步骤、实拍证据、明确价格/规格、来源说明；
- 「现金」本身是交易条件，不是信任机制；
- 若只有「假店」字样但没有辨别依据，不能称为完整信任机制。

### 7.4 互动引擎

- 必须来自评论摘要、明确的 `observed_audience` 评论信号或其他可追溯互动证据；
- 输出触发话题和互动行为，不把「到港游客」「价格敏感」等人群标签直接当作互动机制；
- 没有评论相关证据时保留该行并标记证据不足。

### 7.5 扩散风险

- 区分三类：合规风险、品牌争议、竞品导流；
- 「假店」只有在无证据指控或可能引发名誉争议的语境下才构成风险；
- 「出现原料质疑」「评论导流其他品牌」可作为争议或流失信号，但必须显示证据来源。

### 7.6 内容空白

分三级：

1. `sample_uncovered`：当前样本未覆盖；
2. `opportunity_hypothesis`：样本未覆盖，且存在评论/搜索需求信号；
3. `validated_opportunity`：已有自然或付费测试结果支持。

仅凭「自有卖点未命中竞品主题」最多生成 `sample_uncovered`。不得在分析阶段自动写成「可规模化机会」。

## 8. Prompt 与 Agent 约束

模块1 Prompt 调整为：

- 输入确定性分析产生的结构化事实和证据边界；
- 不再让 LLM 重做事实分类或覆盖 `commonality_rows`；
- LLM 负责把已确认洞察转成「本周测什么、对谁测、观察什么指标」；
- 若行动建议引用未证实的内容空白，必须使用「假设」「待验证」；
- 与事实层冲突的模型输出不写入看板，并进入 `human_review_items`。

## 9. 现有页面融合位置

改进内容直接进入：

- 「赛道与竞品深度分析」第 03 章的 `commonality_rows`；
- 自然流量部分的共性与空白摘要；
- 竞品投放拆解的定向测试卡片；
- 反制动作中的验证建议；
- Markdown/JSON 报告对应章节。

不新增新的入口、页签或独立结果页。

## 10. 错误与降级处理

- 缺评论、发布时间、互动量时不报错；对应维度显示证据不足和补数建议；
- LLM 未配置或调用失败时，返回完整确定性分析；
- 模型输出与事实层冲突时，以事实层为准；
- 手工 `competitor_benchmark_brief` 继续兼容，但自动分析路径使用相同的新增结构字段；
- 旧数据没有新增字段时，前端继续使用 `dimension/observation` 正常显示。

## 11. 测试与验收

采用测试驱动开发，先补失败测试：

1. 珍妮曲奇 3 条样本的自动表达到达手工金样的结构质量；
2. 单篇样本不得被称为跨样本共性；
3. 无评论证据不得生成确定的互动引擎；
4. 「现金」不得自动归入信任机制；
5. 「假店」不得无条件归入扩散风险；
6. 自有卖点未被覆盖时只能输出样本未覆盖或待验证假设；
7. `dimension/observation` 保持兼容；
8. 新证据字段能序列化并进入现有看板；
9. LLM overlay 不覆盖确定性事实行；
10. 无模型 Key 时仍能通过全部核心金样测试。

验收时优先运行聚焦测试，再运行全量测试。当前宿主 Python 环境缺少 `httpx`，优先使用项目 Docker 测试路径；若 Docker 不可用，再修复本地虚拟环境。

## 13. 完成标准

- 不理想样例中的字段混淆全部由自动化测试覆盖并修复；
- 优化内容实际出现在现有「赛道与竞品深度分析」中；
- 无模型 Key 时输出仍然可信；
- 现有 API 和前端不发生破坏性变化；
- 聚焦测试和全量测试通过，或明确记录与本次变更无关的既有失败。
